# 구조와 안전 경계

## 구성

- `validation.py`: URL, 시간 범위, 구간별 파일 제목과 출력 폴더 검증
- `job_files.py`: 버전이 지정된 `.ytdjob` JSON의 전체 검증과 원자적 저장
- `tools.py`: 프로젝트 `bin` 및 안전한 절대 `PATH`에서 yt-dlp와 동일 폴더의 ffmpeg·ffprobe 검색
- `commands.py`: 사용자 입력과 분리된 yt-dlp 인자 목록 구성
- `process_control.py`: Windows 시스템 도구를 이용한 다운로드 프로세스 트리 종료
- `updater.py`: 공식 안정판 `yt-dlp` 설치 및 원자적 업데이트
- `app_updates.py`: 공식 YTDownloader 정식 릴리스 확인과 설치 자산 검증
- `gui.py`: PySide6 화면, 다중 구간 대기열, 비동기 업데이트와 `QProcess` 다운로드 제어
- `deployment`: 고정된 외부 자산 검증, PyInstaller 폴더형 패키징, Inno Setup 설치 파일과 GitHub Release 생성

## 외부 프로세스 정책

외부 명령은 셸 문자열이 아니라 프로그램 경로와 인자 목록으로 전달합니다. yt-dlp의 사용자 설정, 플러그인, 원격 구성 요소, 다운로드 후 명령과 작업 중 자체 업데이트는 비활성화합니다. URL은 지원하는 HTTPS YouTube 단일 영상 경로와 11자리 영상 ID까지 검증하고 `--` 뒤의 마지막 인자로 전달합니다. ffmpeg와 ffprobe는 같은 폴더에 있는 쌍만 사용합니다. 영상은 병합이 필요 없는 단일 형식으로 선택된 경우에도 최종 컨테이너가 MP4가 되도록 후처리하고, 다운로드와 후처리 양쪽에서 기존 파일 덮어쓰기를 금지합니다.

여러 구간은 각 구간을 독립된 yt-dlp 작업으로 만들어 등록 순서대로 실행합니다. 따라서 구간마다 다른 출력 템플릿을 사용할 수 있습니다. 모든 구간의 시간, 제목, 기존 출력 파일과 제목 중복을 첫 작업 전에 검증하며 한 작업이 실패하면 뒤 작업은 시작하지 않습니다. Windows에서 취소하거나 창을 닫으면 시스템 `taskkill.exe`를 절대 경로와 고정 인자로 실행해 yt-dlp와 그 자식 프로세스를 함께 종료합니다.

작업 파일은 하나의 로컬 `.ytdjob` 파일만 받습니다. 크기, UTF-8 인코딩, JSON 중복 키, 스키마 버전, 허용 필드, URL, 구간 수, 시간 순서와 제목 중복을 모두 검사한 뒤에만 현재 화면을 교체합니다. 저장할 때는 같은 폴더의 임시 파일에 기록한 뒤 원자적으로 교체합니다. 컴퓨터마다 달라지는 저장 폴더와 민감할 수 있는 쿠키 파일은 작업 파일에 포함하지 않습니다.

시작 시 업데이트는 프로젝트 `bin`의 앱 소유 `yt-dlp`만 대상으로 합니다. GitHub 공식 최신 안정판 API가 제공하는 자산 크기와 SHA-256을 검증하고, 임시 파일의 버전 실행이 릴리스 태그와 일치한 뒤 기존 파일과 교체합니다. 검증이나 교체에 실패하면 정상인 기존 파일을 유지합니다.

앱 자체 업데이트는 자동 설치하지 않습니다. 시작 시 공식 GitHub 최신 릴리스의 태그, 저장소 주소, 설치 자산 상태와 SHA-256 형식을 검증하고 현재 버전보다 새 버전일 때만 릴리스 페이지를 안내합니다. 사용자가 제외한 버전은 `QSettings`에 기록하여 다시 알리지 않으며, 이후 더 높은 버전은 다시 안내합니다.

공식 Windows 설치본은 사용자별 Local AppData에 설치합니다. 폴더형 실행 파일을 사용하여 Qt 공유 라이브러리를 교체 가능한 상태로 유지하고, 자동 업데이트 대상인 `bin/yt-dlp.exe`에도 사용자 쓰기 권한을 제공합니다. 빌드 입력인 외부 실행 파일, 라이선스와 대응 소스는 `deployment/assets.json`의 HTTPS 주소, 크기와 SHA-256으로 고정합니다. GitHub Actions도 커밋 SHA로 고정하며 앱 버전과 같은 태그에서만 릴리스를 생성합니다.

Windows용 Qt는 운영체제가 제공하는 ICU를 사용합니다. 빌드 머신의 `PATH`에 다른 프로그램용 ICU가 있으면 PyInstaller가 이를 오인해 포함할 수 있으므로 패키징 정리 단계에서 앱 내부의 ICU DLL을 제거합니다. 같은 이유로 OpenSSL과 libffi DLL은 `PATH`에서 수집한 파일을 신뢰하지 않고, 빌드에 사용한 Python 배포본의 원본으로 다시 복사해 SHA-256을 확인합니다. 이후 숨김 Qt 창과 HTTPS 컨텍스트를 실제 이벤트 루프에서 초기화하는 설치 검사가 성공해야만 설치 프로그램 생성을 계속합니다.

일반 푸시와 풀 리퀘스트에서는 단위 테스트와 구문 검사를 실행합니다. 태그 릴리스에서는 별도 권한의 빌드 작업과 게시 작업을 사용하고, 설치·실행·제거 검사와 게시 전 체크섬 재검증을 모두 통과한 자산에만 GitHub 빌드 출처 증명을 생성합니다. FFmpeg 의존 대응 소스는 고정한 FFmpeg-Builds 스크립트가 GPL 공유 변형에 선택한 소스만 별도 아카이브로 만들며 각 내부 아카이브의 SHA-256도 기록합니다.
